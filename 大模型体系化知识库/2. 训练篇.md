### 3. 对齐类微调

**目标**：教模型什么回答更好

#### PPO

PPO是大模型RLHF（基于人类反馈的强化学习）的奠基性技术，它构建了一套精密而复杂的“教学评估体系”。

**核心比喻**：一所拥有“三堂会审”制度的精英学院。

- **学生（Actor Model）**：我们要训练的主力模型。
- **训练数据**：只有**问题（Query）**，没有标准答案。例如：“如何解释引力波？” 模型必须自己独立思考并生成答案。

**关键的“三位一体”评委团：**

1. **Reward 模型（RM）- “客观阅卷官”**：
   - **职责**：对模型生成的每一个答案，给出一个绝对的分数（如0-100分）。
   - **特点**：必须绝对公正。它通常由另一个AI（如GPT-4）担任，或通过大量人类偏好数据训练而成。答案“北京”得高分，答案“上海”得零分。
2. **Critic 模型（价值模型）- “私人心理教练”**：
   - **这是PPO最精妙也最难理解的部分**。既然有了阅卷官，为什么还需要教练？
   - **核心问题**：分数会“欺骗”学生。做“1+1=2”得100分，做一道复杂的微积分题可能只得60分。学生会想：“那我以后只挑简单题做就好了！”这不利于挑战难题。
   - **教练的作用**：Critic模型会评估**题目本身的预期难度**和**学生的当前水平**。对于“1+1”，它预期学生就该拿100分，实际拿了100分，**优势（Advantage）为0**，没有额外奖励。对于微积分题，它预期学生只能拿10分，结果学生拿了60分，**优势高达+50**！这会获得巨大奖励。
   - **本质**：Critic的作用是**消除题目难度差异带来的评分偏差**，鼓励模型勇于挑战并超越自我预期。
3. **Reference 模型 - “初心紧箍咒”**：
   - 这是SFT阶段训练好的模型的一个**冻结副本**，参数不更新。
   - **职责**：防止模型“耍小聪明”（Reward Hacking）。有时模型会发现，输出一堆乱码、无关信息或极端冗长的内容，反而能骗过Reward模型拿到高分。Reference模型就像一面镜子，时刻提醒学生：“看看你原来的正常样子！”如果当前生成的答案与Reference模型的输出概率分布偏离太远，就会受到惩罚，防止模型行为“跑偏”。

**PPO总结**：学生在“客观打分”、“因材施教”和“不忘初心”的三重监督下，每一步更新都小心翼翼（“近端”优化），稳步变强。代价是**计算成本极高**，需要同时加载和交互Actor、Critic、Reward、Reference四个模型，对显存是巨大考验。



#### GRPO

GRPO（组相对策略优化）—— DeepSeek的“群体赛马”哲学

**核心比喻**：一场内部“创意大赛”或“小组头脑风暴”。

- **关键创新**：**裁掉了“私人教练”（Critic模型）**。这一下子省去了近一半的核心显存开销，是技术上的大胆简化。
- **如何评估“优势”？**：GRPO采用了一种巧妙的“群体基线”法。
  1. **组内竞争**：对于同一个问题，让模型**一次性并行生成多个（例如4个或8个）不同的答案**。
  2. **规则评分**：针对数学、代码等有明确对错的任务，使用**规则函数**（如答案是否正确、代码能否运行通过）为每个答案打分（如对=1分，错=0分）。这取代了需要训练的Reward模型，更客观、成本更低。
  3. **计算相对优势**：计算这个小组答案的**平均分**。某个答案的得分如果高于平均分，它就是“优等生”，获得正向奖励；低于平均分，则是“待改进生”，获得负向惩罚。

神奇的副作用：涌现“思维链”
这种“生多个孩子，让它们内部竞争”的机制，产生了一个意想不到的效果：模型自发地学会了“逐步推理”。
模型在试错中发现，对于复杂问题，直接蒙答案很难成为小组里的“优等生”；但如果把思考步骤一步步写出来（生成思维链CoT），得出正确答案的概率和稳定性就大大提升，从而更容易获得高分奖励。
这种深度思考的能力，不是被“教”出来的，而是被GRPO的赛制环境“逼”出来的。 （注：这种并行生成仅发生在训练阶段，上线推理时模型仍是单次生成，不影响速度）。



#### DPO / IPO / KTO

PPO和GRPO都绕不开“评分”环节（无论是RM评分还是规则评分）。DPO则提出了一个更极简、更优雅的思路：**我们能不能连“打分”都省了？**

**核心比喻**：一位“品味鉴赏家”的养成。

- **训练数据**：不是问题和单一答案，而是**问题 + 一对对比答案**：一个人类标注者**偏好**的答案（Chosen），和一个**不偏好**的答案（Rejected）。例如：
  - Query：“介绍你自己。”
  - Chosen：“你好，我是DeepSeek，一个乐于助人的AI助手。”
  - Rejected：“我是AI。”
- **核心目标**：DPO不要求模型绝对提高对好答案的生成概率，而是**极致地拉大“好答案”与“坏答案”在模型眼中的差距**。
- 一个反直觉的例子：
  - 训练前，模型对好答案“北京”的生成概率是99%，对坏答案“上海”的概率是1%。
  - 训练后，模型对“北京”的概率可能**降到了70%**，但对“上海”的概率**骤降到0.0001%**。
  - **这算训练失败了吗？不！这正是DPO的成功**。好坏答案之间的概率差距从98个百分点拉大到了近70个百分点，模型现在**无比确信“上海”是糟糕的选择**，即使它对“北京”的绝对信心有所波动。

**DPO总结**：它绕过复杂的奖励建模，**直接基于人类偏好进行优化**。训练极其稳定，显存占用小（通常只涉及一个主模型），特别擅长**精细化调整模型的风格、语气、安全性和对话品味**，但不太适合解决数学、代码等有绝对对错的任务。

### 参数调优

#### 学习率

线性Warmup预热 + 余弦退火衰减

```python
import math

def get_lr(it, all, args):
    """
    自定义学习率调度策略：线性Warmup预热 + 余弦退火衰减
    GPT/Llama 大模型预训练标准学习率方案，分三阶段变化
    
    参数:
        it: int，当前全局训练迭代步数（step）
        all: int，总衰减迭代步数，一般传入整体训练总步数
        args: 配置参数对象，需包含属性：
              - warmup_iters: warmup预热的步数
              - learning_rate: 峰值最大初始学习率
    返回:
        float: 当前迭代对应的学习率
    """
    # 1. 读取配置超参数
    warmup_iters = args.warmup_iters       # warmup持续步数
    lr_decay_iters = all                   # 余弦衰减完整截止步数
    min_lr = args.learning_rate / 10       # 衰减下限最小学习率，固定为峰值lr的1/10

    # 阶段1：Warmup线性预热阶段
    # 训练初期模型权重随机初始化，学习率从0缓慢线性上升至峰值，避免训练震荡发散
    if it < warmup_iters:
        return args.learning_rate * it / warmup_iters

    # 阶段2：超出总衰减步数，学习率固定为最小值不再下降
    if it > lr_decay_iters:
        return min_lr

    # 阶段3：余弦退火平滑衰减区间（warmup结束后 ~ 总衰减步数前）
    # 计算当前在衰减窗口内的进度比例，取值范围 [0, 1]
    decay_ratio = (it - warmup_iters) / (lr_decay_iters - warmup_iters)
    # 强制约束比例合法，防止浮点越界
    assert 0 <= decay_ratio <= 1, f"decay_ratio={decay_ratio} 超出合法范围"

    # 余弦衰减系数：由cos(π*x)生成平滑下降曲线，系数从1平滑降至0
    coeff = 0.5 * (1.0 + math.cos(math.pi * decay_ratio))

    # 最终学习率 = 最小值 + 余弦系数加权的学习率差值
    lr = min_lr + coeff * (args.learning_rate - min_lr)
    return lr
```

#### Q5：大模型后训练，为什么先SFT再DPO？

```tex
1. 明确分工：先“学会答”，再“挑选怎么答得更好”。
	SFT 阶段使用高质的 (Prompt, Response) 指令对，教模型学会基础的指令遵循能力、多轮对话格式、语言风格以及输出结构的规范。
	DPO 的目的是在模型已经能够生成合理回答的前提下，引导模型倾向于输出质量更高、更安全、逻辑更严密、符合人类偏好的内容（Chosen），抑制低质量或有危害的内容（Rejected）。
	
2. DPO 的数学公式依赖于一个高质量的参考模型（Reference Model）
	在实际训练中，参考模型 πref 通常直接初始化为 SFT 后的模型。
 	基座模型对指令 Prompt 的概率分布极度不稳定，计算出来的πref(y|x)值极其混乱甚至会出现概率接近 0 的数值，这会导致 DPO 的梯度极易爆炸或失效。
 	使用 SFT 模型作为起点，保证了πθ和πref在训练初期处于同一个基本合格的输出分布中，KL 散度约束才能有效防止模型“退化”或“产生幻觉”。
 	
3. 数据分布与训练稳定性（防止分布偏移与语言崩溃）
	如果直接对 Base 模型应用 DPO,Base 模型从未见过这种结构化的指令数据，面临巨大的分布偏移（Distribution Shift）。直接用对比损失去强行拉高 Chosen 的概率、降低 Rejected 的概率，极易导致模型出现：语言退化和格式崩溃。
	
4. 缩小搜索空间（Search Space Reduction）
	Base 模型的潜在生成空间是无穷大的（包含各种网页文本、代码、乱码、多语言混合等）。
	SFT 模型将这个巨大的空间缩小到了一个较小的**“合法回答空间”**。
	DPO 只需要在“合法回答空间”内搜索最优解。
	
补充：是否有方法可以跳过 SFT？
	ORPO (Odds Ratio Preference Optimization) 和 SimPO 等方法尝试将 SFT 的交叉熵损失（SFT Loss）和偏好优化损失结合在一个 Loss 中，直接在 Base 模型上进行训练。
```

$$
L_{DPO} = −E_{(x,y_w,y_l)}[logσ(βlog\frac{π_θ(y_w|x)}{π_{ref}(y_w|x)}−βlog\frac{π θ(y_l|x)}{π_{ref}(y_l|x)})]
$$

#### Q6：在垂类模型的预训练时，如何选择是使用 **SFT** 还是 **Continued Pretraining** 的方式？

1. 领域知识差异度（Knowledge Gap）—— **最关键因素**

- **差异极大（建议：Continued Pretraining + SFT）**：
  - 领域内有大量通用模型未见过的**专有词汇、特殊符号、私有代码库、特定行业术语**（如医学病历、法律条文、金融高频交易代码、古籍等）。
  - 基座模型在评估测试中对该领域的专业概念频繁出现“幻觉”或完全不知道。
- **差异较小（建议：直接 SFT）**：
  - 领域知识本身在互联网通用数据中已经广泛存在（如常规编程语言、通用客服对话、公网常见的心理咨询等），基座模型其实“知道”，只是“答得不够专业/格式不对”。

2. 手头数据的形态与规模（Data Readiness）

- **拥有海量非结构化文本（建议：Continued Pretraining）**：
  - 数据主要是大量文档、书籍、PDF、规范、代码库、行业报告（百兆/GB/TB级别）。
  - 将这些文本改写成高质 QA 格式成本极高。
- **拥有高质量问答/指令对（建议：直接 SFT）**：
  - 数据主要是“问题-答案”对、业务 Task 标注、多轮对话记录（千条到几十万条）。

3. 算力与成本预算（Budget & Resource）

- **预算充足（GPU 资源丰富，追求极强专业度）**：
  - 选择 **Continued Pretraining + SFT** 组合拳。
- **预算有限 / 快速落地**：
  - 优先选择 **直接 SFT**，或者结合 **RAG（检索增强生成）** 架构。增量预训练的算力消耗和调参成本远高于 SFT。

4. 任务的复杂程度（Task Type）

- **开放式文本理解、生成与深层推理**：如基于整本专业手册进行逻辑推理，需要 Continued Pretraining 提升基座的领域上下文理解力。
- **确定性任务、格式化输出**：如 JSON 提取、分类、特定风格判研、客服应答，SFT 就能取得非常好甚至更好的效果。



#### Q7：灾难性遗忘与“对齐税”

- **混合预训练数据（Data Replay）**：在 SFT/RLHF 训练数据中混入 5%~10% 高质量的预训练通用数据。
- **对齐损失正则化**：在损失函数中增加原始语言模型损失（NLL Loss），约束模型在偏好更新时不要偏离原概率分布太远。
- **参数高效微调（LoRA/DoRA）与冻结策略**：对于特定轻量级对齐，限制更新的权重范围；或只训练顶层/特定模块。



#### Q8：数据污染

- **严格的去重与反污染过滤**：使用 N-gram 重合度、Embedding 相似度在数据清洗阶段剔除任何与标准测试集重合的样本。
- **动态/私有评测集（Dynamic Evaluation）**：建立每周更新的隐蔽测试集，依靠人工评测（Human Eval）或基于最新真实用户日志的 LLM-as-a-Judge 评估。

### 6. 算法与训练稳定性问题

#### Q1：奖励黑客/奖励崩塌（Reward Hacking）

- **现象**：在 RLHF 阶段，奖励模型（Reward Model）得分很高，但生成的文本质量极差（如出现严重的重复、无限套用礼貌客套话、长篇大论但毫无实质内容）。
- **原因分析**：Goodhart 定律生效 —— Policy（策略模型）找到了 Reward Model 的漏洞，利用 RM 的评估盲区（如倾向于给长文本、格式漂亮、态度好的回答打高分）来刷高分。
- **解决方案**：
  - **强化 KL 散度约束**：增大与初始 Policy（SFT 模型）之间的 KL 散度惩罚系数 β，防止策略模型偏离太远。
  - **长度惩罚（Length Penalty）**：在 Reward 归一化时扣除过度冗余的长度收益。
  - **RM Ensemble / 集成奖励**：使用多个架构/数据训练的 RM 取最小值或均值作为最终 Reward。
  - **在线/迭代式 RLHF（Iterative / Online RLHF）**：定期用新 Policy 采样的样本重新训练 RM，动态更新 RM 的认知。





### 7. 训练 Loss 与梯度异常

#### Loss 骤升 / 出现尖峰（Loss Spike）

- **现象**：Loss 在平稳下降过程中，突然出现几倍甚至几十倍的瞬间暴涨，随后可能缓慢回落或直接无法收敛。
- **常见原因**：训练数据中混人了异常长文本、极劣质/乱码数据；梯度爆炸；学习率（LR）过大且没有合理的 Warmup；混合精度训练（如 FP16）下数值溢出。

#### Loss 剧烈震荡（Loss Oscillation）

- **现象**：Loss 曲线呈锯齿状剧烈上下波动，无法平滑下降。
- **常见原因**：Batch Size 设置过小，梯度噪声大；学习率（LR）过高，模型在局部极小值附近“过冲”；数据 Shuffle 不均匀，不同 Batch 间数据分布差异巨大。

#### Loss 过快降为 0 或崩塌（Loss Collapse / Early Convergence）

- **现象**：SFT 或 DPO 训练初期，Loss 在极少 Step 内迅速接近 0。
- **原因**：严重过拟合（如数据集太小或格式过于单一）、掩码（Data Masking）逻辑写错（例如将 Prompt 和 Output 全部当作 Target 算 Loss，或者掩码掉了大部分有效 Token）。

#### Loss 不下降 / 卡住（Loss Plateau / Stagnation）

- **现象**：从训练开始 Loss 就几乎是一条直线，或者下降非常微弱。
- **常见原因**：学习率太小；Prompt 和 Target 的 Loss Mask 设置错误（例如把输入 Prompt 的 Loss 也计算了，或者把 Output 的 Loss 给 Mask 掉了）；参数冻结（Freeze）设置错误，漏解冻了关键层；超参数（如 DPO 的 β）设置过于激进。

#### Loss 变为 NaN / Inf（Loss 飞掉）

- **现象**：Loss 突然变成 NaN（Not a Number）或 Inf（Infinity），训练直接中断或输出全部变成垃圾字符。
- **常见原因**：FP16 数值下溢/上溢（除零或 log(0)）；梯度爆炸未做 Clip（Gradient Clipping）；Softmax 或 Log 计算中出现 log(0) / div by 0；未加 eps 防护；或者 RL 中的 Log Probability 计算溢出。

#### DPO Loss 持续下降但模型性能崩溃 / Loss 变为极小负数

- **现象**：在 DPO 训练中，Loss 一直急剧下降（甚至降到非常小的负数），但评测指标（如 AlpacaEval、GSM8K）大幅下滑。
- **常见原因**：DPO 的隐式 Reward 发生过拟合；β 参数设得太小，导致模型过度偏离 Reference Model；数据集中存在噪点（Chosen 和 Rejected 标注反了）

#### KL 散度爆炸或骤降为 0（KL Divergence Explosion / Collapse）

- **现象**（RLHF / DPO 等）：Actor 与 Reference 模型的 KL 散度极速上升（超过十几甚至几十）或始终接近 0。
- **原因**：KL 惩罚系数（kl_coef）太小导致模型脱缰，或太大导致模型不敢探索；DPO 中学习率过高导致模型倾向于强行拉大胜负项概率差。



###  8. 模型生成与文本质量类异常

#### 文本死循环与刷屏重复（Repetition / Degenerate Loops）

- **现象**：模型输出连续重复的字词、短语或整段话（如“我是……我是……我是……”或无限循环句尾符号）。
- **原因**：SFT 数据中包含大量重复文本；RL 过程中的惩罚机制失效；采样温度（Temperature）或 Top-p 过低；位置编码在超长序列上失效。

#### 模式坍塌与回答单一（Mode Collapse / Lack of Diversity）

- **现象**：无论用户问什么，模型都使用同一种固定的句式、模版或话术回答（例如极度依赖“作为 AI 语言模型…”、“首先、其次、最后”的机械化套路）。
- **原因**：偏好对齐（DPO/PPO）过拟合，模型找到了能够稳定获取高 Reward 的“安全区间”，放弃了回答的多样性。

#### 语种漂移与乱码（Language Drift / Gibberish）

- **现象**：输入中文，模型回答突变成英文、法语或无意义的 Unicode 乱码、控制字符。
- **原因**：单语种 SFT 数据比例失衡，破坏了基座模型的 Tokenizer / 嵌入层（Embedding）；或强行在没有能力基底的语种上做强化学习。

#### 长度暴增 / 恶化（Length Exploitation / Length Bias）

- **现象**：模型的生成长度越来越长，充斥着废话和车轱辘话，甚至触发 Max Tokens 截断。
- **原因**：奖励模型（Reward Model）倾向于给长文本打高分（Length Bias），Actor 模型借此“刷分”。

#### 过度拒答（Over-refusal / Sycophancy）

- **现象**：
  - **过度拒答**：询问无害问题（如“如何在 Linux 中 kill 一个进程？”），模型触发安全机制并拒绝回答。
  - **阿谀奉承（Sycophancy）**：哪怕用户给出明显错误的事实，模型也无脑迎合用户观点。
- **原因**：安全/对齐数据（Safety SFT/RLHF）占比过高、正负样本泛化性不足，或者对偏好数据进行了机械式的正反馈强化。

#### 灾难性遗忘（Catastrophic Forgetting）

- **现象**：在特定领域（如代码、数学）后训练后，通用对话能力、多轮历史理解能力或原本支持的长文本能力剧烈下滑。
- **原因**：后训练数据域太窄、退火阶段未混合通用预训练/SFT 数据（Replay Data）。

#### 特殊 Token 泄漏与模版失效（Special Token Leakage）

- **现象**：模型输出中直接打印出 <|im_start|>、</s>、<thought>、User: 等系统标签，或者多轮对话格式错乱。
- **原因**：SFT 预处理中对模板（Chat Template）的解析或 Masking 逻辑不正确，导致模型将控制符作为普通文本进行了学习。
