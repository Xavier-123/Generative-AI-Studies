# 🐛 Badcase 分析与归因 — 金融级大模型高可靠抗幻觉推理系统

> **定位**：评测指标体系（测得准）→ **Badcase 归因（错在哪）** → 模块修复（怎么改）→ 回归评测（改没改好）
> **归因方法**：分层回溯法 —— 回答错了先看证据召回（检索层），再看证据对不对（忠实度），最后看推演过程（推理层）；每条 badcase 沿流水线从末端往回追，定位到首个出错环节。
> **口径说明**：分布占比为示例口径（与消融表 B1/B4 假设数据自洽），实际项目以线上回流 + 评测集复判数据为准。

## 一、Badcase 分类总表

按流水线阶段分为六族 19 类。**频率** = 该类占全部 badcase 的比例（完整系统 B4 口径）；**严重度** = 金融业务后果（资金决策 > 合规风险 > 体验问题）。

| 族 | ID | 类型 | 一句话定义 | 频率 | 严重度 |
|:---|:---:|:---|:---|:---:|:---:|
| 🧭 意图与路由 | A1 | 意图误判 | 复杂多跳问题被当单跳简单问答处理 | 2% | 高 |
| | A2 | 计算工具未触发 | 数值题走了"心算生成"而非计算器/工具调用 | 4% | 高 |
| | A3 | Query 改写漂移 | HyDE/改写丢失原问题的时间、实体约束 | 3% | 中 |
| 🔍 检索层 | R1 | 多跳断链 | 第一跳证据召回，第二跳证据缺失或错招 | 26% | 高 |
| | R2 | 时效/版本错配 | 召回旧报告期、旧版监管文件顶替最新版 | 12% | 高 |
| | R3 | 实体消歧失败 | 同名/简称混淆（母公司 vs 子公司、同名基金） | 9% | 高 |
| | R4 | 排序失效 | 正确证据在召回集内但排名靠后（Lost-in-the-Middle） | 5% | 中 |

| | G2 | 数值篡改 | 单位/位数/正负号/小数点错误（3.2亿→32亿） | 8% | 高 |
| | G3 | 张冠李戴 | A 公司的数据安到 B 公司头上 | 3% | 高 |

| 🧠 推理层·逻辑幻觉 | L1 | 多跳中间结论错误 | 第二跳建立在未经验证/错误的中间答案上 | 6% | 高 |
| | L2 | 数值计算错误 | 增长率/比率/久期等计算过程出错 | 7% | 高 |
| | L3 | 阈值/边界判断错误 | ≥80% 与 >80% 不区分，合规边界判断反了 | 2% | 高 |
| | L4 | 时间序列逻辑错误 | 跨报告期比较时基期/口径不一致 | 3% | 高 |
| 🔄 验证反思层 | V1 | 验证问题带毒 | CoV 生成的验证问题本身有预设偏差，错答被"验证通过" | 3% | 中 |
| | V2 | 过度修正 | 反思把原本正确的答案改错（Reflexion 震荡） | 2% | 中 |
| ⚖️ 拒答校准 | Q1 | 强答 | 证据不足仍给出确定性结论 | 4% | 高 |

> 面试一句话：**残留 badcase 的重心已经不在"编造"，而在"检索不全 + 数值处理"** —— 这直接决定了下一阶段的优化优先级。

## 二、各族典型案例 · 根因 · 修复映射

### 🧭 意图与路由层

| ID | 典型案例 | 根因 | 修复手段 | 验证指标 |
|:---:|:---|:---|:---|:---|
| A1 | 问"该集团旗下子公司谁的资产负债率最高"（需先列子公司再逐个查），系统单次检索直接作答 | 意图分类器未识别多跳信号 | ReAct 路由规则 + 多跳判别 prompt；意图分类样本补充 | Multi-hop 准确率 |
| A2 | 问"近三年净利润 CAGR"，模型逐 token 心算得出 18.7%（正确 17.2%） | 路由未触发计算工具，走了自由生成 | 路由层加"含数值计算"硬规则；计算类 query 强制走 Tool/代码解释器 | 数值计算正确率（程序化校验） |
| A3 | 问"2024 年报中……"，HyDE 假设文档把年份改写成"近年来"，召回混入 2022/2023 数据 | 改写丢失约束 | 改写保留原 query 关键槽位（时间/实体/指标）做受控改写；改写前后 Recall 对照 | HyDE/改写增益 |

### 🔍 检索层（残留 badcase 最大来源，占 ~56%）

| ID | 典型案例 | 根因 | 修复手段 | 验证指标 |
|:---:|:---|:---|:---|:---|
| R1 | 问"A 持股的 B 公司的担保余额"，A 的持股证据召回成功，B 的担保公告未召回 | 第二跳 query 依赖第一跳结果，检索是静态的 | Agentic 迭代检索：第一跳结论改写第二跳 query；Cross-Encoder 精排阈值放宽后补召回 | Recall@10、Multi-hop 准确率 |
| R2 | 问 2024 年报数据，答案引用 2023 年报（两份都召回且旧版相似度更高） | 索引未带时间权重；精排未区分报告期 | 元数据过滤（年份/版本优先）+ 精排特征加时效分；索引去重保留最新版 | 时效错配专项准确率 |
| R3 | "华泰证券"与"华泰联合证券"混淆；同名基金不同基金公司 | Dense 向量对实体区分度弱 | 实体链接/消歧前置；BM25 精确匹配加权（混合召回的价值场景） | 实体消歧专项集准确率 |
| R4 | 正确证据排在第 8 位，模型只重点读了前 3 条（Lost-in-the-Middle） | 精排模型对该 query 排序错误；长上下文注意力偏置 | Cross-Encoder 换更强精排模型；证据重排（关键信息前置） | MRR、nDCG@10 |
| R5 | 子切片命中"抵押率 68%"，但父文档下一句"含 2024 年新增质押后为 75%"被切断 | Small-to-Big 扩展窗口设置不当 | 滑动窗口扩展策略调优；父子映射覆盖率检查 | 引用覆盖率 |

### ✍️ 生成层 · 事实幻觉（CoV + LoRA 后已压至低位，但残留类型更隐蔽）

| ID | 典型案例 | 根因 | 修复手段 | 验证指标 |
|:---:|:---|:---|:---|:---|
| G1 | 证据只提到"应收账款周转率下降"，回答编造了"周转天数为 142 天" | 参数知识补位（证据缺失时模型用先验补全） | 拒答策略（证据覆盖度不足时触发）；CoV 对每个数字溯源 | 幻觉率、FActScore |
| G2 | 证据"3.2 亿元"，回答写"32 亿"或"3,200 万"；"下降 5 个百分点"写成"下降 5%" | 数字 token 化失真；百分比/百分点概念混淆 | 数值抽取后程序化复写（不走生成）；单位规范后处理 | 数值计算正确率 |
| G3 | 多公司上下文中，A 的营收数据被安到 B 头上 | 长上下文实体-属性绑定错误 | 证据按实体切分喂入；生成时强制"数值+主体"配对引用 | Faithfulness |
| G4 | 证据"部分子公司未纳入合并范围"，回答"子公司均未纳入" | 量词/限定词语义漂移 | LoRA 批判数据集加入量词改写负样本；Judge rubric 加量词检查项 | FActScore |
| G5 | 两份证据冲突（业绩预告 vs 正式年报），模型引用了过期的预告值 | 冲突识别能力不足 | 证据冲突检测 + 时效优先级规则；对应"证据冲突"对抗样本与 LoRA 批判训练 | 证据冲突子集准确率 |

### 🧠 推理层 · 逻辑幻觉

| ID | 典型案例 | 根因 | 修复手段 | 验证指标 |
|:---:|:---|:---|:---|:---|
| L1 | 第一跳算出持股 51%，第二跳直接按"全资"口径推导控制关系 | 中间结论未验证即被下游引用 | 中间结论强制过 CoV 验证；推理链每步挂证据引用 | Multi-hop 准确率 |
| L2 | 逾期率 = 逾期贷款/贷款总额，分母用成了贷款笔数 | 心算 + 公式召回错误 | 计算类步骤代码化执行（Tool），推理只负责列公式 | 数值计算正确率 |
| L3 | 合规规则"单一客户授信集中度 ≤ 10%"，实测 10.2% 判为"达标"（边界含等号误判） | 边界条件在自然语言中歧义 | 规则类判断走结构化规则引擎，模型只做抽取不做判罚 | 数值计算正确率 |
| L4 | 用 2024 三季报的年化数据和 2023 年报直接比增速 | 口径/基期未对齐 | 时间口径抽取为结构化字段；跨期比较强制口径检查 | 时间序列专项集 |

### 🔄 验证反思层（反思机制自身引入的新问题）

| ID | 典型案例 | 根因 | 修复手段 | 验证指标 |
|:---:|:---|:---|:---|:---|
| V1 | CoV 验证问题是"该公司抵押率是否达标？"（预设了达标），错误答案被验证放行 | 验证问题由同一模型生成，偏差同源 | 验证问题改写为开放式（"抵押率是多少？是否高于阈值？"）；验证与生成分池采样 | 幻觉率（CoV 消融组） |
| V2 | 答案本正确，反思一轮后"自我怀疑"改成错误答案 | Reflexion 对"证据充分性"评估过严 | 反思触发条件加置信度门槛（仅低置信触发）；修正需新证据支撑而非纯推理 | 反思前后正确率差值 |
| V3 | Self-Consistency 5 次采样一致地给出同一个错误值（系统性偏差而非随机噪声） | 一致性 ≠ 正确性；错误源于共享的检索缺陷 | 一致性分数与证据覆盖度交叉校验；一致但无溯源的答案降级处理 | 逻辑一致性 + 幻觉率联合看 |

### ⚖️ 拒答校准

| ID | 典型案例 | 根因 | 修复手段 | 验证指标 |
|:---:|:---|:---|:---|:---|
| Q1 | 证据只有"担保总额"，问"对单一被担保方余额"时模型用行业常识估算作答 | 拒答阈值过松；证据覆盖度判定缺失 | 证据覆盖度打分 + 拒答阈值校准；对应"不可答问题"对抗样本 | 拒答正确率 |
| Q2 | 证据充分（数据在表格后半段），模型答"资料未披露" | 证据利用率不足被误判为缺失 | 表格解析增强；拒答前强制二次检索 | 拒答正确率（另一侧） |

> **Q1 与 Q2 是同一根校准曲线的两端**：阈值收紧 → 强答减少、幻觉式拒答增加。报告时必须同时给出两条子集（可答集准确率 + 不可答集拒答率），只报一边没有意义。

## 三、Badcase 结构演变：B1 → B4（系统有效性证据）

| Badcase 族 | B1 Naive RAG 占比 | B4 完整系统占比 | 变化解读 |
|:---|:---:|:---:|:---|
| ✍️ 生成·编造型（G1/G3） | 25% | 3% | **CoV + LoRA 压住了无中生有** —— 生成侧幻觉基本清除 |
| 🧠 推理·计算型（L 族） | 18% | 18% | 占比没降反升？因总量下降（幻觉率 18%→4%），**绝对量降了约 80%** |
| 🔍 检索缺失型（R1/R2/R3） | 30% | 47% | 成为残留 badcase 主体 —— **问题重心从生成侧转移到检索侧** |
| ⚖️ 校准型（Q 族） | 8% | 6% | 拒答机制净收益为正 |
| 🔄 反思引入型（V 族） | 0% | 5% | **新增成本项**，反思不是免费的 —— 对应成本-效果 Pareto 曲线 |

**结论（面试叙事）**：badcase 结构决定优化路线 —— B1 阶段"幻觉大头在生成"，上 CoV/Reflexion/LoRA；B4 阶段残留大头变成"多跳断链 + 数值处理"，下一步投入检索补全（Agentic 迭代检索）与计算工具化，而不是继续加深反思层数（边际收益递减、延迟上升）。

## 四、归因 SOP：一条 badcase 的定位流程

```
线上用户纠错 / 评测集失败样本
  │
  ① 复现：同 query 重跑，固定 seed，保存全链路日志（意图→query改写→召回列表→精排分数→推理链→验证结果）
  │
  ② 检索层检查：必需证据句在不在召回集？（对照"问题→必需证据"标注）
  │     ├─ 不在 → 检索 badcase（R 族）→ 看是召回缺失还是排序问题（逐层看 Dense/BM25/精排分数）
  │     └─ 在 → 继续
  ③ 忠实度检查：错误 claim 是否被证据支撑？
  │     ├─ 不支撑 → 生成 badcase（G 族）→ 检查是编造、篡改还是错配
  │     └─ 支撑但答案错 → 推理 badcase（L 族）→ 检查中间结论与计算过程
  ④ 若反思后仍错 → V 族 → 检查验证问题质量与修正逻辑
  ⑤ 打标入库：ID + 根因 + 修复方案 + 回归用例
  │
  ⑥ 修复后回归：badcase 转入回归测试集，每次发版全量重跑，防复发
```

> ①的**全链路日志**是前提 —— 没有每阶段中间产物落盘，归因只能靠猜。这也是面试常问的"你们的可解释性怎么落地"：答案就是阶段级中间产物 + badcase 归因路径。

## 五、Badcase ↔ 评测体系闭环

| 对抗样本 / 评测集 | 覆盖的 badcase | 检测指标 | 修复归属模块 |
|:---|:---|:---|:---|
| 不可答问题子集 | Q1 / Q2 | 拒答正确率 | 拒答阈值校准 |
| 证据冲突子集 | G5 | 冲突识别准确率 | LoRA 批判数据集 |
| 数字陷阱子集 | G2 / L2 / L3 | 数值计算正确率（程序化） | 工具化计算 + 规则引擎 |
| 多跳子集（FinQA/ConvFinQA） | R1 / L1 | Multi-hop 准确率 | Agentic 迭代检索 |
| 自建"问题-证据-答案"三元组 | R2 / R3 / R4 / R5 | Recall@10 / MRR / nDCG | 混合召回 + 精排 + 元数据过滤 |

**闭环**：对抗样本按 badcase 类型定向构造（不是随机凑数）→ 评测暴露 → 归因到模块 → 修复 → badcase 入回归集。每类 badcase 都有"检测指标 + 修复模块"两个锚点，保证消融表（评测指标体系·附表 B）里每个模块的边际增益都能对应到具体被消灭的 badcase 类型。

## 六、处理决策框架：先分级，再选手段

### 6.1 优先级矩阵（频率 × 业务严重度）

处理顺序不是"谁先发现修谁"，按 **频率 × 严重度** 分四档：

| | 高危（资金决策/合规误判） | 中危（数据陈旧/张冠李戴） | 低危（表述/体验） |
|:---|:---|:---|:---|
| **高频** | P0：规则硬防当天上线，根因修复排期跟进 | P1：进迭代版本 | P2：观察池，攒批处理 |
| **低频** | P0/P1：规则兜底 + 攒样本等微调 | P2：攒批 | 记录在案，明确不修 |

> 金融场景的严重度排序：**算错的数字 > 错过的合规边界 > 过期的数据 > 措辞问题**。一条高频低危的 case 永远排不到一条低频高危前面。

### 6.2 修复手段阶梯：确定性优先

核心原则一句话：**能用确定性手段解决的，绝不交给概率性手段。**

```
L1 硬规则 / 工程校验      ← 确定性 100%，当天可上线，但只能治可形式化的错误
L2 工具化                 ← 把"生成"变"执行"：计算走代码解释器，输出必经校验器
L3 检索层修复             ← 修证据供给：Query 改写/迭代检索/元数据过滤/换精排
L4 Prompt / 流程编排      ← 模型有能力、流程没约束：验证问题改写、拒答阈值、反思触发条件
L5 SFT / LoRA             ← 模型能力缺失：量词语义、冲突识别、证据遵循
```

**逐级下探的判据**（跳级 = 浪费成本）：

| 层级 | 适用判据 | 典型 badcase | 成本 / 迭代周期 |
|:---:|:---|:---|:---|
| L1 | 错误模式可完全形式化（单位/位数/阈值/正负号/引用必填） | G2、L3 | 小时级 |
| L2 | 任务本质是确定性计算或校验（CAGR/比率/久期/合规阈值） | L2、G2 | 天级 |
| L3 | 根因在证据侧：证据没召回 / 召回错 / 排序差 | R1–R5 | 天～周级 |
| L4 | 模型有该能力，但流程未约束或引导错误 | A1、V1、Q1 | 天级 |
| L5 | **prompt 对照实验修不动的能力缺失**，且同类样本可积累 ≥ 50 条 | G4、G5 | 周级，需防泄漏评测集 |

> 面试高频追问"什么时候用微调、什么时候用 prompt"——判据就一条：**先做 prompt 对照实验，修不动 + 样本可积累 + 有防泄漏评测，三者齐备才进 L5**。凡是用规则和工具能兜住的（数值、阈值），微调永远不是答案——微调提升的是概率，规则保证的是确定。

### 6.3 修不了的就降级：拒答 → 转人工 → 限场景

修复不是唯一出路，**金融场景的兜底链**：

```
置信度 < 阈值 或 证据覆盖度不足 → 拒答（附"缺哪类证据"的说明）
关键数字未过校验器 → 输出但挂"待人工复核"标记
某类 query 持续高错 → 路由降级回规则系统/模板回答，等修复后再放开
```

> 拒答率是设计出来的安全边际，不是缺陷——宁可 Q2（幻觉式拒答）小幅上升，也不让未校验的数字直接进信贷审批材料。

## 七、各族标准处理路径

| 族 | 首选手段 | 次选 | 兜底 | 关键备注 |
|:---|:---|:---|:---|:---|
| 🧭 A 意图路由 | L4 路由规则（多跳判别、计算类硬规则触发工具） | L5 意图分类样本 | 降级单跳 + 明示局限 | A2 必须走 L2，心算无解 |
| 🔍 R 检索 | L3（迭代检索 / 元数据时效过滤 / 实体消歧） | L5 精排模型微调 | 证据置信度不足触发拒答 | R2 靠元数据过滤，改模型没用 |
| ✍️ G 事实 | L1 数值校验器 + L4 CoV 逐 claim 溯源 | L5 批判数据集 | 拒答 | G2 首选 L1：单位/位数校验是纯规则问题 |

## 八、修复验证：防"按下葫芦浮起瓢"

每个修复动作跑**五步验证**，缺一不可：

1. **单例转绿**：触发修复的 badcase 本身复测通过
2. **回归全量**：回归集（历史 badcase + 全量评测集）重跑，无退化
3. **消融对照**：所属模块的边际增益 Δ（消融表）不缩水
4. **灰度验证**：10% 流量上线，线上幻觉率 / 用户纠错率环比不升
5. **复发监控**：badcase 打标签监控，同类再犯自动告警并回滚

其中第 2 步的**反向指标**最容易被漏掉——RAG 系统里每个修复动作都可能把问题挤到相邻环节：

| 修复动作 | 目标指标 ↑ | 反向指标（不许掉） |
|:---|:---|:---|
| 收紧拒答阈值（压 Q1） | 不可答集拒答率 | **可答集准确率**（Q2 会升） |
| 加深反思轮数（压 G 族） | Faithfulness | TTFT / P99 延迟、V2 过度修正率 |
| 扩大召回窗口（压 R1） | Recall@10 | 时效错配率、噪声导致的 Faithfulness 下降 |
| LoRA 批判训练（压 G5） | 证据冲突子集准确率 | 通用基准能力（防灾难性遗忘） |
| 精排换更强模型（压 R4） | MRR / nDCG@10 | 精排延迟（在线环节 P99） |

> 面试叙事：我们考核修复的标准不是"这条 case 好了"，而是"**目标指标上去 + 相邻指标没掉**"——单向优化在 RAG 系统里几乎必然把问题推到下一环节。

## 九、长尾 badcase：低频不等于不处理

高频 case 逐条修，低频 case 靠机制收：

| 机制 | 做法 | 目的 |
|:---|:---|:---|
| 聚类归并 | 残留 badcase 做_embedding 聚类，按簇看根因 | 表面 30 条不同的 case 可能同一根因，修一处治一簇 |
| Case 增殖 | 1 条 badcase 构造 10–20 个变体批量测 | 判断孤例（记录不修）还是系统性缺陷（必须修） |
| 攒批微调 | 低频同类进 SFT 样本池，凑够量级随下轮训练消化 | 避免为个例 case 单独发版 |
| 明确不修 | 记录决策与理由（修复成本 > 风险敞口） | 防止同样的 case 被反复重报 |

---

> **全流程一句话**：发现（线上纠错 + 评测）→ 归因（分层回溯）→ 分级（频率 × 严重度）→ 选手段（L1→L5 确定性优先）→ 验证（双向指标 + 回归）→ 沉淀（回归集 + 监控标签）。badcase 处理体系的产出不是"修了多少条"，而是**每类错误都有明确的归属层、修复路径和回归防线**。
