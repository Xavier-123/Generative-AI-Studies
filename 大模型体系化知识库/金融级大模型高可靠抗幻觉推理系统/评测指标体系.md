# 📊 评测指标体系 — 金融级大模型高可靠抗幻觉推理系统

> **适用范围**：Agentic RAG 离线评测 + 上线后在线监控
> **评测器**：RAGAS + LLM-as-a-Judge（人工校准）+ 程序化确定性校验
> **优先级图例**：`P0` 必须有 · `P1` 重要 · `P2` 加分项

---

## 一、主指标总表

| 层级 | 指标 | 定义 / 测什么 | 评测方法 | 目标值（示例） | 优先级 |
|:---|:---|:---|:---|:---|:---:|
| 🔍 **检索层** | Recall@K（K=5/10） | 多跳问题所需的全部证据篇目是否被召回 | 自建"问题→必需证据句"标注对，程序化命中判定 | Recall@10 ≥ 90% | P0 |
| | MRR | 第一条正确证据排名倒数的均值 | 同上 | ≥ 0.75 | P1 |
| | nDCG@10 | 证据排序的整体质量 | 同上 | ≥ 0.85 | P1 |
| | 混合召回增益 | Dense+BM25 相对单路 Dense 的 Recall 提升 | 消融对比 | ≥ +5pt | P2 |
| | HyDE/改写增益 | Query 改写前后的 Recall 差 | 消融对比 | ≥ +3pt | P2 |
| ✍️ **生成层** | Faithfulness 忠实度 | 回答中的 claim 被检索证据支撑的比例 | RAGAS faithfulness | ≥ 85%（裸基线约 40–50%） | P0 |
| | Answer Accuracy | 回答与金标准答案的一致率 | 精确匹配 / Judge 评分 | ≥ 80% | P0 |
| | FActScore | 回答拆成原子事实后的逐条验证通过率 | 细粒度拆解 + Judge | ≥ 90% | P1 |
| | 引用覆盖率 | 关键数字与结论可溯源的比例 | 规则校验 + Judge | 关键数字 100% | P0 |
| | 幻觉率 | 含事实错误的回答占比 | Judge 判定 + 人工抽检复核 | ≤ 5% | P0 |
| | 拒答正确率（Abstention） | 证据不足时正确说"不知道"的比例 | 不可答问题子集专项评测 | ≥ 90% | P0 |
| 🧠 **推理层** | Multi-hop 准确率 | ≥2 跳推理题目的正确率 | 多跳子集单独切档 | ≥ 75% | P0 |
| | 数值计算正确率 | 比率/久期/合规阈值判断的正确率 | 程序化确定性校验（无需 Judge） | ≥ 95% | P0 |
| | 逻辑一致性 | 同一问题多次采样的答案一致率 | Self-Consistency 前后方差对比 | 方差显著下降 | P2 |
| ⚙️ **工程层** | TTFT | 首 token 延迟 | vLLM vs HF 裸推理压测 | ↓ 30%+ | P1 |
| | P99 端到端延迟 | 99 分位完整回答延迟 | 压测 | 视业务达标线 | P1 |
| | 吞吐 QPS | 动态批处理后的吞吐量 | 压测 | 记录绝对值 | P2 |
| | 成本-效果 Pareto | 每提升 1% 忠实度的额外 token/延迟成本 | 分档触发反思策略实验 | 平均成本增幅 < 2× | P1 |
| ⚖️ **评测器质量** | Judge-人工一致率 | LLM Judge 与人工标注的一致性 | 100–200 条人工标注抽检 | Cohen's Kappa > 0.7 | P0 |
| | 位置偏差 | Pair-wise 比较时的顺序影响 | 交换答案顺序双跑 | 偏差 < 5pt | P1 |
| 📡 **在线监控** | 用户纠错率 | 用户对回答点"有误"的比例 | 埋点 | 环比下降 | P1 |
| | 引用点击率 | 用户点开引用核验的行为 | 埋点 | 观察指标 | P2 |
| | 忠实度漂移 | 定期回流样本复评的指标变化 | 月度抽检复评 | 无显著劣化 | P1 |

> **口径说明**：报告"提升 25%+"时必须注明是**绝对百分点**（如 58%→83%）还是**相对提升**（如 50%→62.5%），面试与汇报中最常见的追问点。

## 二、附表 A：基线对照体系

所有指标在同一批测试集、同一评测器下对比，数字才可比。

| 基线 | 配置 | 目的 |
|:---:|:---|:---|
| B0 | Qwen3.5 裸模型，不检索 | 量化"幻觉底座"，证明检索价值 |
| B1 | Naive RAG：单粒度切块 + Dense 单路召回，无重排 | 工业界最常见 baseline |
| B2 | B1 + 混合召回 + Cross-Encoder 精排 + HyDE | 隔离"检索优化"的贡献 |
| B3 | B2 + CoV + Self-Consistency + Reflexion + LoRA | 端到端最终值 |

## 三、附表 B：消融实验归因模板

| 配置 | Faithfulness | Multi-hop 准确率 | 幻觉率 | 边际增益 Δ |
|:---|:---:|:---:|:---:|:---:|
| B0 裸模型 | 41% | 22% | 31% | — |
| B1 Naive RAG | 58% | 39% | 18% | +17 |
| B2 +检索优化 | 66% | 51% | 12% | +8 |

## 四、评测集构成

| 数据源 | 用途 | 规模建议 |
|:---|:---|:---|
| FinQA / ConvFinQA / TAT-QA / FinanceBench | 公开集打底，可信可引用 | 全量 |
| 自建"问题-证据-答案"三元组（年报/研报/监管文件） | 主评测集 | 300–500 条 |
| 对抗性样本：不可答问题 | 测拒答（Abstention） | 50–100 条 |
| 对抗性样本：证据冲突 | 测冲突识别（对应 LoRA 微调目标） | 50–100 条 |
| 对抗性样本：数字陷阱 | 测数值幻觉 | 50–100 条 |

> **防泄漏**：微调数据与评测集按来源/时间切分（如微调用 2023 年报、测试用 2024 年报），证明 LoRA 提升的是能力而非拟合测试集。
